# Transfer loading states

The transfer flow uses visible progress for first loads and text-labeled progress for consequential actions. Skeletons are static shapes without shimmer. On the home screen, sage placeholders replace visible loading copy for balance and recipient loads, including refreshes; their loading labels remain available to assistive technology. Error states retain visible status text.

| Operation           | Initial wait                                                                                                                                                                                                                                                                                                      | Refresh with cached data                                                                                                                                                                                                             |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Account balance     | Sage balance skeleton with an accessible “Loading balance…” label and no visible loading copy. On a network error, timeout, or paused offline request, show a compact connection visual and explanation in the balance area. The draft remains editable, but review is unavailable until account data is present. | Show the balance skeleton without visible loading copy. On connection failure, restore the last known balance, identify it as such, and show a small connection warning in the balance area.                                         |
| Saved recipients    | Compact sage selector skeleton with an accessible “Loading recipients…” label and no visible loading copy. Picker access is disabled until a successful recipient response exists; manual entry remains available.                                                                                                | Show the selector skeleton without visible loading copy. Cached recipients remain accessible during refreshes, offline states, and refresh failures. Keep manual entry available. If the selection disappears, require a new choice. |
| Transfer approval   | Busy action with spinner and “Approving transfer…”, including PIN verification. Block duplicate requests and navigation while pending; incorrect PIN or PIN cooldown returns to PIN entry with the server error.                                                                                                  | Not applicable.                                                                                                                                                                                                                      |
| Transfer submission | Busy action with spinner and “Sending transfer…”. Block navigation and duplicate requests while pending. An uncertain result uses the existing unresolved-submission recovery flow.                                                                                                                               | Not applicable.                                                                                                                                                                                                                      |
| Transfer lookup     | Receipt skeleton and “Loading transfer…” when no cached receipt exists.                                                                                                                                                                                                                                           | Keep cached receipt visible.                                                                                                                                                                                                         |

The recipient control opens a full-screen page with search by name or account number only when a successful recipient response exists, including an empty list. Cached data qualifies even during a refresh or after a refresh failure. Without data, both the selector and its loading skeleton are disabled. A direct visit without data shows only a simple unavailable message and a Back to transfer action. The picker reads the shared cache without initiating requests; detailed loading, error, and recovery behavior belongs on the transfer form. Choosing a saved recipient returns to the transfer form immediately; Back leaves the selection unchanged. Search clears when leaving the page. “Enter manually” returns to the transfer form and reveals name and account fields there; the form also offers a direct manual-entry action. Errors and offline states remain explicit and actionable.

Pulling down on the transfer form refreshes the account balance and saved recipients together, including during initial loading or after an error. The pull indicator remains visible until both requests settle or the device goes offline, and another pull during that refresh does not start more requests. The recipient, amount, and note draft stays intact. The balance and saved-recipient selector show skeletons while fetching; manual recipient fields stay visible. Errors remain visible; if the selected saved recipient disappears, the sender must choose another.

The balance connection state tells the sender to pull down to refresh; it has no separate retry button. When the device is offline, a cached balance is identified as last known, and a pull does not start another request or leave a spinner running. A paused initial query continues when connectivity returns. A recipient failure does not replace the transfer form or the balance state; manual recipient entry remains available. Other balance failures use the same inline pink exclamation visual as recipient errors, with a balance-specific title and pull-to-refresh guidance. When cached balance data exists, keep it visible above the notice.

Recipient connection failures use the same compact connection visual as the balance, with recipient-specific copy. Other recipient failures use a restrained pink error visual with an exclamation mark and explicit error text. Both appear inline in the recipient section and direct the sender to pull down to refresh; there is no separate retry button. Cached lists remain usable and are described as potentially out of date. Manual entry remains available in every state.
